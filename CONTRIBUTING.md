# Contributing to PELLAIRI PEDS

Thank you for helping improve PEDS. These steps make changes easier to review and safer to merge.

## Before opening a pull request

1. Open an issue for a substantial change, or explain the problem and proposed scope in the pull request.
2. Create a focused branch from the latest `main`; do not commit directly to `main`.
3. Keep each change focused. Do not include credentials, tokens, personal information, or unrelated database changes.
4. Update documentation when behavior, schema, workflow, or policy changes.
5. Run the checks relevant to the files you changed and include the commands and results in the pull request. If a path filter skips a check, do not claim that check passed.

## Pull request review

- Explain the reason for the change, its scope, risks, and verification.
- Request review from a maintainer. The author must not count their own review as independent approval.
- Resolve review conversations before merging.
- Do not merge while required checks fail or while a material review concern remains open.
- If the project has no independent reviewer available, leave the change unmerged until a reviewer is available. Do not use an administrator bypass as a substitute for review.

## Security and conduct

Follow [SECURITY.md](SECURITY.md) for private vulnerability reports. Follow the [Code of Conduct](CODE_OF_CONDUCT.md) in project spaces. Do not put vulnerability details in a public issue or pull request.
